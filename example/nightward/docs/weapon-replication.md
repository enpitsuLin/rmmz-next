# 六种武器的原版表现与节奏

1. **来源与职责**

   以 [官方 Nightward 发布脚本](https://goodstuff.pixijs.io/nightward/assets/start-DZtWMAL3.js) 中的实际模拟参数和绘制代码为准。

   `scripts/import-reference-combat.mjs` 使用共享的 TypeScript 符号依赖提取器，将原版六武器的绘制模块、粒子着色器、命中效果和镜头后处理导出为 `js/nightward/reference/combat.js`。文件头记录来源和 SHA-256，应通过生成脚本维护。

   `weapon-effects.ts` 将本工程的角色、飞弹、法典、法阵、火池和战斗事件提供给绘制模块。攻击、伤害、成长和状态仍由 `RunSession`、RMMZ `Game_Action` 和数据库负责；没有引入原版游戏模拟器或另一套 PixiJS 引擎。

2. **武器表现**

   | 武器 | 绘制内容 |
   | --- | --- |
   | Lash | 随时间扫过的三层弧形鞭迹、亮边、火花、闪点与局部光照 |
   | Wand | 发射闪光、多层光核、旋转星光、光束拖尾、余烬与命中爆光 |
   | Tomes | 环绕书本、启动爆光、火焰丝带、尾焰、地面光环与升降摆动 |
   | Storm | 多段分叉雷电、二次闪烁、火花、碎片、冲击环、地面焦痕、天空闪光与镜头反馈 |
   | Ward | 多层光环、双向旋转符文、随伤害节拍扩散的脉冲、尘雾与上升光点 |
   | Flask | 抛物线、瓶身旋转、尾焰、破碎爆燃、碎片、持续橙色火焰与燃尽焦痕 |

   已撤下原有扁平鞭圈、单点飞弹、竖向闪电贴图、普通法阵圆环和绿色火池。镜头后处理使用原版闪光、冲击波、炫光、色彩分级和颗粒着色器，取代此前的简化色彩滤镜，避免重复叠加。HUD 与原生窗体不经过世界后处理。

3. **出手节奏**

   | 武器 | 首次出手等待 | 连发或特殊节奏 |
   | --- | --- | --- |
   | Lash | 0.30 秒 | 二阶起在前击后 0.16 秒反向攻击 |
   | Wand | 0.40 秒 | 同轮飞弹相隔 0.08 秒 |
   | Tomes | 0.30 秒 | 0.25 秒进入、0.30 秒退出；完全退出后停转；同一敌人重复命中相隔 0.45 秒 |
   | Storm | 0.80 秒 | 同轮落雷相隔 0.07 秒 |
   | Ward | 0.20 秒 | 按数据库间隔造成伤害；视觉脉冲在 0.35 秒内衰减 |
   | Flask | 0.60 秒 | 同轮投掷相隔 0.09 秒；飞行 0.55 秒；火池每 0.35 秒结算一次伤害 |

   各阶伤害、冷却、数量、半径和持续时间来自 `Weapons.json` 的备注数据。连发等待期间升级，后续出手使用当前等级；已抛出的药瓶保留投掷时的等级。法典在活动期间升级会同步数量和半径，不重置当前持续时间。

   模拟顺序按原版依次处理武器、既有火池和飞行物，药瓶落地后从下一次模拟结算火池伤害。火池保留原版最多 32 个的模拟容量；视觉缓存使用与原版一致的 Float32 时间，防止同一火池被反复登记。

4. **被动效果**

   - Cinder 每级减少 8% 冷却：`基础间隔 × (1 - 0.08 × 等级)`，同时作用于法典休眠。五阶为基础间隔的 60%。
   - Haste 每级增加 10% 移速：`基础移速 × (1 + 0.10 × 等级)`。
   - Cinder 不再减免受到的伤害，Haste 不再影响武器冷却。
   - 连发间隔、鞭子反击延迟、药瓶飞行和火池伤害间隔不受 Cinder 缩放，遵循原版。

   数据库描述和生成脚本同步这些规则。命中事件使用 `Game_Action` 的伤害结果，保留原版重击特效的伤害阈值和击杀时的完整伤害数字。

5. **资产和生命周期**

   `combat-fx.png` 和 `combat-fx.json` 已随工程提供。粒子、光束、地面效果、书本与药瓶由 RMMZ 现有 Effekseer 运行时绘制，沿用原版容量、贴图、轨迹和时序。临时光源与镜头继续使用 Pixi3D。实例随视图销毁停止；共享图集与 EffectManager 资源缓存保留。武器光效跟随世界时间，暂停、升级和宝箱选择期间冻结，新一局重新初始化。资源制作和职责边界见 [Effekseer 说明](effekseer.md)。

   在本工程目录只重新制作武器呈现与图集：

   ```sh
   node scripts/import-reference-combat.mjs
   ```

   重新生成包含装备在内的 RMMZ 数据库：

   ```sh
   node scripts/generate-content.mjs
   ```

   全量 `generate:assets` 也会更新战斗呈现与图集。`NIGHTWARD_REFERENCE_SOURCE` 可指定已缓存的官方脚本；Chrome 仅执行 Canvas 图集制作，不启动游戏。重制数据库会覆盖 Weapons、Armors、Skills 等数据库中的手动修改，保留现有地图布局和事件页。

7. **原生装备构筑**

   - `Weapons.json` 保存六种武器各五阶，共 30 条；`Armors.json` 保存四种被动各五阶，共 20 条，装备类型为饰品。
   - Nightward 职业使用六个武器槽和四个饰品槽，职业特性提供对应的武器和防具装备许可。初始 Lash 一阶来自 Actor 初始装备，职业不再自动学习武器技能。
   - 升级和宝箱共用装备替换流程：同系列替换原槽，新系列进入对应类型的第一个空槽，保留获得顺序，不在背包累积淘汰的旧阶装备。标题演示同样使用原生装备。
   - HUD、暂停页和结算读取 `Game_Actor.equips()`。死亡只清除临时状态，装备等级继续保留，无需结算前缓存构筑。
   - `Skills.json` 仅保留六个武器内部攻击模板和两个敌方攻击动作。每件武器的原生“添加技能”特性（`code: 43`）关联该家族的内部攻击模板，`damage` 提供该阶独立基础伤害；模板承载伤害类型、元素和原生效果，命中由 `Game_Action` 结算。装备的八项基础参数默认为零，避免把六件武器的伤害相加。
   - 饰品备注的 `value` 表示当前总倍率，沿用 Might 10%、Haste 10%、Lodestone 35%、Cinder 8% 的每阶数值。永久构筑不再依赖学习技能或被动状态。
   - 名称、描述、图标使用数据库原生字段。武器备注只保存 `key`、`rank` 与独立伤害、冷却、数量、范围和轨迹参数；饰品备注只保存 `key`、`rank`、`value`。不再重复保存名称、描述、图标、类别，也不保存未使用的颜色。
   - 每件武器配置一条“添加技能”特性，技能 ID 取自该特性的 `dataId`。出手与命中逐件读取来源武器的绑定，不通过角色汇总技能或 `attackSkillId()` 选择，六件武器可同时运行各自攻击。装备提供的技能由原生特性系统管理，无需 learnSkill；不保留备注 skillId 的兼容读取。
   - 原始数据库对象保留身份，用于原生 `Game_Item` 和装备接口；备注只在内容载入时解析。出手、飞弹、火池和 Effekseer 生命周期保持原有规则。

   数据职责依据 [RMMZ 官方武器与防具说明](https://rpgmakerofficial.com/product/MZ_help-en/01_08_05.html)。本次未运行自动化验证或游戏，由用户自行测试。
